# 04. Docker Terminology

A glossary of the core Docker terms you'll run into constantly.

## Image
A **read-only template** containing the application code, runtime, libraries, and dependencies needed to run an app. Images are built from a Dockerfile and are immutable — once built, they don't change (you build a new image for changes).

## Container
A **running instance of an image**. If an image is the blueprint, a container is the actual live, running object created from that blueprint. You can start, stop, restart, and delete containers.

## Dockerfile
A **text file with a set of instructions** used to build a Docker image. Contains commands like `FROM`, `WORKDIR`, `COPY`, `RUN`, `EXPOSE`, `CMD`.

## Docker Hub
A **public registry/repository** where Docker images are stored and shared. You can pull ready-made images (like `nginx`, `mysql`, `node`) or push your own images to share with others.

## Registry
A more general term for a storage/distribution system for Docker images. Docker Hub is the default public registry, but private registries (e.g., AWS ECR, GitHub Container Registry) also exist.

## Volume
A mechanism for **persisting data** generated by containers. Since containers are ephemeral (data is lost when a container is deleted), volumes let you store data outside the container's writable layer so it survives container restarts/removal.

## Network
Docker's built-in system for **allowing containers to communicate** with each other and with the outside world. By default, containers get their own isolated network, but you can create custom networks to let specific containers talk to each other (e.g., an app container talking to a database container).

## Docker Compose
A tool for **defining and running multi-container applications** using a single YAML file (`docker-compose.yml`). Instead of manually running multiple `docker run` commands, you define all your services (app, database, cache, etc.) in one file and spin them up together with `docker-compose up`.

## Tag
A **label/version identifier** attached to an image, e.g., `nginx:1.25` or `myapp:latest`. Helps track different versions of the same image.

## Layer
Each instruction in a Dockerfile creates a **layer** in the image. Layers are cached and stacked on top of each other to form the final image.

## Bind Mount
Similar to a volume, but maps a **specific folder on the host machine** directly into the container — useful during development so code changes reflect immediately without rebuilding.
